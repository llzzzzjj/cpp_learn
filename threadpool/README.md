# C++11 线程池

## 项目简介

本项目使用固定数量的工作线程处理提交的函数任务。

任务先进入共享队列，工作线程取出任务后执行。
没有任务时，工作线程通过条件变量等待，避免不断循环检查队列。

等待队列具有容量上限，队列满时拒绝新任务。

- C++11
- CMake 3.16 及以上

## 接口说明

### 创建线程池

```cpp
ThreadPool pool(2, 64);
```

创建两个工作线程，等待队列最多保存 64 个任务。
正在执行的任务不占等待队列容量。

省略第二个参数时，默认容量为 64。
线程数或容量为零时，抛出 std::invalid_argument 异常。

### 提交任务

```cpp
bool submit(Task task);
```

任务类型为 std::function<void()>，即无参数、无返回值的函数对象。

- 返回 true：任务已被接收，不代表已经执行完成。
- 返回 false：任务为空、线程池开始停止，或者等待队列已满。
- 提交失败后，由调用者决定放弃、稍后重试或采取其他处理方式。

### 停止线程池

```cpp
void shutdown();
```

停止接收新任务，唤醒工作线程，并等待所有已接收任务处理完毕。
不会主动丢弃队列中已接收的任务。

支持同一个外部控制线程先后重复调用。
当前不支持多个线程同时调用，也不能在工作任务内部调用。

如果任务一直不返回，shutdown() 也可能一直等待。

### 析构行为

析构函数自动调用 shutdown()。
因此，即使使用者没有主动停止，线程池销毁时也会等待工作线程结束。

## 并发处理

任务队列和停止标记由同一把互斥锁保护。

工作线程持锁取出任务，释放锁后执行任务，
使其他线程仍然能够提交或取出任务。

任务抛出普通 C++ 异常时，工作线程记录错误并继续处理后续任务。
失败任务不会自动重试。

任务访问外部共享数据时，需要自行保证同步和对象生命周期；
线程池的队列锁不会自动保护任务内部的数据。

## 构建与测试

在项目根目录执行：

```bash
cmake -S . -B build
cmake --build build
```

进入构建目录运行测试：

```bash
cd build
ctest --output-on-failure
```

查看详细输出：

```bash
ctest -V
```

构建产物：

- libthreadpool.a：线程池静态库。
- threadpool_test：测试程序。

## 已验证的测试

- 队列满时拒绝新任务。
- 主动停止、停止后拒绝提交和重复停止。
- 拒绝空任务。
- 单个任务异常后，工作线程继续处理其他任务。
- 多生产者提交时，接收、拒绝与执行总数符合预期。

以上五项测试已通过。
CTest 将整个测试程序注册为一项测试，超时限制为 30 秒。

## 当前限制

- 工作线程数量在构造时确定，不支持动态调整。
- 不支持通过接口取得任务返回值。
- 不支持取消已经接收的任务。
- 当前完成了功能验证，尚未进行性能评估。
